# ExperimentLab

ExperimentLab is a small A/B-testing and product analytics toolkit built with Python and DuckDB. It covers experiment assignment checks, treatment-effect estimation, variance reduction, bootstrap uncertainty, power planning and an explicit decision policy.

All example observations are generated by the repository and are synthetic.

## Decision report

Generate a standalone browser report directly from the experiment warehouse:

```bash
python -m experimentlab.report --output build/experiment-decision.html
```

The report combines:

- SRM assignment-integrity evidence;
- control/treatment conversion rates, absolute lift and a 95% confidence interval;
- the pre-specified minimum useful conversion effect;
- support-contact guardrail change and configured harm threshold;
- deterministic bootstrap uncertainty for revenue per assigned user;
- the approximate conversion MDE supported by the current per-arm sample size;
- the explicit `ship`, `hold` or `do_not_ship` decision and its reasons.

The generated HTML includes its own CSS and requires no application server. The decision policy uses interval evidence and guardrails rather than a p-value alone. The report is labeled as a synthetic scenario and does not present its result as real product uplift.

## Analysis flow

1. Check assignment integrity with a Sample Ratio Mismatch (SRM) test.
2. Reconcile assignment and outcome grains.
3. Estimate the treatment effect and confidence interval.
4. Apply CUPED only with a valid pre-treatment covariate.
5. Use bootstrap intervals for skewed outcome differences where appropriate.
6. Evaluate guardrails before making a recommendation.
7. Compare the result with the pre-specified minimum useful effect.

## Included methods

- two-proportion z-test with absolute and relative lift;
- 95% confidence interval for conversion-rate differences;
- CUPED adjustment;
- deterministic percentile bootstrap for treatment-minus-control mean differences;
- `ship`, `hold` and `do_not_ship` decision policy;
- equal-allocation sample-size planning for binary outcomes;
- minimum detectable effect (MDE) calculation from a fixed per-arm sample budget.

The power utilities use a normal approximation for two independent proportions. They assume a fixed-horizon analysis and do not account for repeated unplanned looks at the data.

## Example

```python
from experimentlab import minimum_detectable_effect, required_sample_size_per_arm

plan = required_sample_size_per_arm(0.10, 0.015, power=0.80)
print(plan.sample_size_per_arm)

mde = minimum_detectable_effect(0.10, sample_size_per_arm=20_000)
print(mde.absolute_mde)
```

## Run and test

```bash
python -m pip install -e '.[dev]'
ruff check .
ruff format --check .
pytest -q
python -m experimentlab.report --output build/experiment-decision.html
```

CI runs on Python 3.11 and 3.12.

## Limitations

- The current dataset is synthetic and exactly controlled for reproducibility.
- Sequential-testing corrections are not implemented yet.
- Multiple-testing controls across secondary metrics are not implemented yet.
- The current decision policy is intentionally explicit and rule-based rather than a claim of universal product-decision logic.

## Roadmap

- add funnel event tables and retention cohorts;
- add guardrail uncertainty rather than point-estimate-only checks;
- demonstrate sequential-look inflation and multiple-testing corrections;
- add report sections for funnels/retention when those marts exist;
- add heterogeneous treatment-effect analysis only with adequate sample size and pre-specification.
